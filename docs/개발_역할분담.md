## 1. 협업 방식

이 프로젝트는 Pull Request를 사용하지 않는다. 각 담당자는 본인의 기능 브랜치에서 작업하고, 작업 단위별로 커밋한 뒤 원격 브랜치에 push한다. 통합 담당자는 각 브랜치를 로컬에서 병합하고 통합 실행을 확인한 후 `main`에 push한다.

### 담당 브랜치

| 담당자 | 브랜치 | 책임 영역 |
|---|---|---|
| 김낙근 | `feature/rag` | 공통 RAG와 검색 도구 |
| 김도현 | `feature/graph-judge` | 공통 스키마, LangGraph, 검증, 채점, 통합 실행 |
| 박세진 | `feature/discover-market-competitor` | 후보 확인, 시장 분석, 경쟁사·특허 분석 |
| 김진형 | `feature/tech-synergy-report` | 기술 분석, 전략 시너지, 투자보고서 |

### 작업 시작

각 담당자는 최초 한 번 다음 명령을 실행한다.

```bash
git switch main
git pull origin main
git switch -c feature/담당-브랜치
git push -u origin feature/담당-브랜치
```

이미 브랜치가 존재하면 다음과 같이 시작한다.

```bash
git switch feature/담당-브랜치
git pull origin feature/담당-브랜치
```

### 커밋 형식

```text
:emoji:[TYPE] 작업 내용
```

| 구분 | 형식 | 사용 기준 |

| 기능 추가 | `:sparkles:[FEAT] 작업 내용` | 새로운 기능이나 모듈 추가 |
| 기능 개선 | `:recycle:[REF] 작업 내용` | 기존 구조나 로직 개선 |

| 테스트 | `:white_check_mark:[TEST] 작업 내용` | 테스트 추가·수정 |
| 설정·패키지 | `:wrench:[CHORE] 작업 내용` | 의존성, 빌드, 환경 설정 |

예시:

```bash
git commit -m ':sparkles:[FEAT] PDF 페이지 단위 로더 구현'
git commit -m ':bug:[FIX] 공통 문서가 기업 필터에서 제외되는 오류 수정'

```

한 커밋에는 가능한 한 하나의 작업 목적만 포함한다. `임시 저장`, `수정`, `작업 중`처럼 변경 내용을 알 수 없는 메시지는 사용하지 않는다.

## 3. 김낙근 작업 내용

### 담당 목표

기술·시장·시너지 등 모든 분석 Agent가 동일하게 호출할 수 있는 로컬 RAG 검색 기능을 완성한다. 검색 결과까지만 책임지며 투자 지표 판단이나 점수 계산은 하지 않는다.

### 담당 경로

```text
rag/
data/manifest.csv
data/documents/
data/index/
evaluation/retrieval_eval.py
evaluation/retrieval_questions.json
```

### 구현 순서

1. 현재 구현된 `models.py`, `manifest.py`, `loader.py`를 기준으로 실제 PDF 적재를 확인한다.
2. 페이지 경계를 넘지 않는 token chunker를 구현한다.
   - 기본 450 tokens
   - overlap 60 tokens
   - 원문 페이지 번호 유지
   - 표 분할 시 제목과 header 반복을 지원할 수 있는 구조 유지
3. `BAAI/bge-m3` Dense embedding을 구현한다.
   - Dense vector만 사용
   - 로컬 실행
   - FAISS 인덱스 저장·불러오기
4. Kiwi tokenizer와 BM25를 구현한다.
   - 한국어 형태소 처리
   - 영문, 숫자, 하이픈이 포함된 기술명 보존
5. Dense Top20과 BM25 Top20을 결합하는 RRF를 구현한다.
   - `k=60`
   - 동일 가중치
6. 검색 필터를 구현한다.
   - `candidate_id`
   - `doc_types`
   - `parent`, `market` 공통 문서는 특정 후보 검색에서도 포함
7. 아래 공개 함수를 완성한다.

```python
def search_documents(
    query: str,
    candidate_id: str | None = None,
    doc_types: list[str] | None = None,
    top_k: int = 5,
) -> list[RetrievedChunk]:
    ...
```

8. 실제 문서로 indexing부터 Top5 검색까지 실행한다.
9. Hit Rate@5, MRR@5, 검색 latency, p50, p95를 측정한다.
10. 설치, 인덱싱, 검색, 평가 명령과 측정 결과를 김도현에게 전달한다.

### 완료 조건

- manifest의 사용 페이지 합계가 200페이지를 넘으면 적재가 중단된다.
- 같은 문서를 재색인해도 불필요한 중복이 생기지 않는다.
- Top5 결과에 `chunk_id`, `source_id`, `doc_id`, `candidate_id`, `doc_type`, `page`, `content`, `score`가 포함된다.
- `page`는 원문 PDF의 페이지 번호다.
- RRF score를 사실의 신뢰도나 확률로 표현하지 않는다.
- 다른 Agent가 `search_documents()`만 import해서 사용할 수 있다.

## 4. 김도현 작업 내용

### 담당 목표

공통 State와 분석 결과 형식을 확정하고 LangGraph의 분기, 근거 검증, 보완, 채점, 후보 순환과 전체 실행을 완성한다. 네 사람의 코드를 최종 통합하는 역할도 맡는다.

### 담당 경로

```text
schemas/
graph/
nodes/review.py
nodes/repair.py
nodes/judge.py
nodes/eligibility.py
nodes/archive.py
nodes/skip.py
app.py
requirements.txt
.env.example
README.md
```

### 구현 순서

1. 다음 공통 모델과 필드명을 먼저 확정해 팀에 공유한다.
   - `GraphState`
   - `AnalysisResult`
   - `IndicatorEvidence`
   - `SourceRecord`
   - `GateResult`
   - `EvaluationRecord`
2. Reducer를 구현한다.
   - `sources`는 `source_id` 기준 병합
   - `evaluations`는 후보별 한 번만 누적
   - 분석 결과는 담당 필드 단위로 갱신
3. Mock Node를 이용해 전체 Graph를 먼저 연결한다.
4. 적격성 분기를 구현한다.
   - PASS이면 심층 분석
   - FAIL 또는 UNKNOWN이면 분석 생략 후 HOLD
5. tech 실행 후 market, competitor, synergy가 모두 완료된 다음 review가 한 번 실행되도록 연결한다.
6. review와 repair를 구현한다.
   - 원문 대응, 단위, 기간, 중복, source 연결 검증
   - 후보당 repair 최대 1회
7. Python 채점 함수를 구현한다.
   - Decimal `ROUND_HALF_UP`
   - G1~G3
   - 12개 지표
   - 자체 발표 최대 3점
   - 자료 없음 처리
   - 70점 경계
8. 후보 선택, 임시 State 초기화, archive와 종료 조건을 구현한다.
9. 실제 Agent를 하나씩 연결하고 전체 후보 실행을 확인한다.
10. 실행 방법, 환경변수, 담당자, 검색 성능과 Lessons Learned를 README에 취합한다.

### 완료 조건

- 후보 2~3개를 순서대로 모두 처리한다.
- 이전 후보의 분석값이 다음 후보에 남지 않는다.
- 동일 후보가 `evaluations`에 중복 저장되지 않는다.
- 적격성 생략 후보의 총점은 `None`이다.
- 전원 HOLD여도 보고서를 생성하고 정상 종료한다.
- 투자 판단은 LLM 문장이 아니라 Python 채점 결과로 결정된다.

## 5. 박세진 작업 내용

### 담당 목표

사전에 확정된 후보의 기본정보를 확인하고 시장 및 경쟁사·특허 분석의 원값과 출처를 공통 형식으로 반환한다. 후보를 자동으로 새로 발굴하거나 최종 투자 판정을 만들지 않는다.

### 담당 경로

```text
agents/discover.py
agents/market.py
agents/competitor.py
prompts/discover.md
prompts/market.md
prompts/competitor.md
data/candidates.json
data/evidence/company/
data/evidence/market/
data/evidence/patent/
```

### 구현 순서

1. 후보 2개를 우선 확정하고 여유가 있으면 세 번째 후보를 추가한다.
2. `data/candidates.json`에 다음 정보를 기록한다.
   - `candidate_id`
   - 법인명과 소재국
   - 법인 식별자
   - 설립일
   - 주력 세그먼트
   - 최근 투자 라운드
   - 상장·법인 조회 경로와 근거 URL
3. `discover`를 구현한다.
   - G1 적격성용 사실
   - T1, R1, R3, F1~F3 원값
   - 창업자 이력, 논문, 정부 연구비 URL을 김진형에게 전달
4. `market`을 구현한다.
   - P1 원값
   - 통계 세그먼트
   - 비교 연도와 계산 기간
   - 한국 도입 시장 기준
5. `competitor`를 구현한다.
   - 경쟁 제품과 기술 비교
   - 공식 특허 조회 결과
   - 우선권 기준으로 중복 제거한 유효 등록 특허 패밀리
   - M1 원값
6. 각 Agent가 김도현이 정한 공통 `AnalysisResult` 형식으로 반환하도록 연결한다.
7. 실제 조회 실패, 자료 부재, 0건을 구분하는 테스트를 작성한다.

### 반환 원칙

```python
def market_node(state: GraphState) -> dict:
    return {
        "market_analysis": analysis,
        "sources": source_records,
    }
```

- State 전체를 반환하지 않는다.
- 자료가 없으면 `raw_value=None`으로 기록한다.
- 정상 조회 결과가 실제 0건이면 `raw_value=0`으로 기록한다.
- 접근 실패를 0건으로 처리하지 않는다.
- 기간, 단위, 분모와 기업 귀속을 기록한다.
- 점수와 INVEST/HOLD 판정은 만들지 않는다.

### 완료 조건

- `company_profile`, `market_analysis`, `competitor_analysis`가 공통 형식으로 반환된다.
- 모든 `source_ids`가 실제 `sources` 기록을 가리킨다.
- 후보별 적격성 확인에 필요한 근거 URL이 준비된다.
- 시장 수치는 적용 세그먼트와 비교 기간을 함께 제공한다.
- 특허는 단순 검색 건수가 아니라 유효 등록 특허 패밀리 기준이다.

## 6. 김진형 작업 내용

### 담당 목표

후보의 기술력과 제조기업 전략 시너지를 분석하고, 검증과 채점이 끝난 전체 후보 State로 5쪽 이내 투자보고서 PDF를 생성한다.

### 담당 경로

```text
agents/tech.py
agents/synergy.py
agents/report.py
prompts/tech.md
prompts/synergy.md
prompts/report.md
reporting/
data/evidence/tech/
data/evidence/parent/
```

### 구현 순서

1. `tech`를 구현한다.
   - T2, K1, K2, K3, R2 원값
   - 기술 요약
   - 시험 횟수, 성공 정의, 작업, 환경과 조건
   - 논문 DOI와 저자 소속
   - 제조 현장 실증 중복 제거
2. `synergy`를 구현한다.
   - S1, S2, F4 원값
   - 후보가 수행한 작업군
   - 모기업 문서의 작업 수요 페이지
   - 방폭 구역과 인증 확인 상태
3. 김낙근의 `search_documents()`를 tech와 synergy에서 공통 호출한다.
4. 김도현의 공통 `AnalysisResult`와 `IndicatorEvidence` 형식으로 반환한다.
5. 보고서 생성기를 구현한다.
   - 1쪽: SUMMARY와 평가 대상
   - 2쪽: 기술과 제조 현장 적용
   - 3쪽: 시장, 경쟁과 평가 종합
   - 4쪽: 위험, 한계와 후속 실사
   - 5쪽: REFERENCE
6. 한글 폰트, 표 잘림, 페이지 수와 source 연결을 검증한다.
7. 실제 사용된 출처만 REFERENCE에 포함한다.

### 반환 원칙

```python
def tech_node(state: GraphState) -> dict:
    return {
        "tech_analysis": analysis,
        "sources": source_records,
    }
```

- State 전체를 반환하지 않는다.
- 기술·시너지 Agent에서 점수나 최종 판정을 만들지 않는다.
- 기업 연구진의 시험은 독립 재현이 없으면 자체 발표로 표시한다.
- 서로 다른 시험 조건의 성공률을 합치지 않는다.
- 보고서에서 새로운 웹 검색 사실을 추가하지 않는다.

### 완료 조건

- `tech_analysis`와 `synergy_analysis`가 공통 형식으로 반환된다.
- K2의 성공률에 전체 시도 수, 성공 시도 수와 시험 조건이 포함된다.
- S2가 모기업 문서의 원문 페이지와 연결된다.
- 검증된 전체 후보 결과로 5쪽 이내 PDF가 생성된다.
- SUMMARY는 첫 페이지 반쪽 이내이며 마지막 페이지는 REFERENCE다.

## 7. 공통 인터페이스

### Agent 반환 규칙

모든 Agent는 담당 분석 필드와 새로 사용한 출처만 반환한다.

```python
def agent_node(state: GraphState) -> dict:
    return {
        "담당_analysis": analysis,
        "sources": source_records,
    }
```

분석 결과는 최소한 다음 정보를 가진다.

```text
candidate_id
summary
indicators
source_ids
query_attempts
```

### 검색 결과 규칙

```text
query
  -> search_documents()
  -> RetrievedChunk[]
```

RAG는 검색된 근거까지만 반환한다. 지표 해석, 근거 검증, 점수와 최종 판정은 김도현 담당 영역이다.

### Source 연결 규칙

- Agent의 모든 `source_ids`는 State의 `sources`에 존재해야 한다.
- PDF 출처는 원문 페이지와 `chunk_id`를 기록한다.
- 웹·API 출처는 응답 또는 문단 식별자를 기록한다.
- 같은 출처를 여러 지표에 사용할 수 있지만 독립 증거가 늘어난 것으로 설명하지 않는다.

## 9. 파일 충돌 방지 규칙

| 파일·영역 | 최종 관리 담당 |
|---|---|
| `rag/`, `data/manifest.csv`, `evaluation/` | 김낙근 |
| `schemas/`, `graph/`, `nodes/`, `app.py` | 김도현 |
| `data/candidates.json` | 박세진 |
| `reporting/`과 보고서 템플릿 | 김진형 |
| `requirements.txt`, `.env.example`, `README.md` | 김도현이 최종 취합 |

공통 파일을 직접 수정해야 할 때는 먼저 최종 관리 담당자에게 필요한 패키지, 필드 또는 문구를 전달한다. 서로 다른 브랜치에서 같은 공통 파일을 동시에 수정하지 않는다.

## 10. 당장 시작할 작업

| 담당자 | 첫 작업 |
|---|---|
| 김낙근 | STEP 3 token chunker 구현 및 원문 페이지 유지 테스트 |
| 김도현 | 공통 스키마 확정 후 Mock Node 기반 Graph 전체 흐름 구현 |
| 박세진 | 후보 2개 확정, `candidates.json` 작성, G1 근거 수집 |
| 김진형 | tech·synergy 출력 형식 구현, 한글 5쪽 PDF 출력 시험 |

첫 통합 시점에는 실제 분석 완성 여부와 관계없이 Mock을 포함한 전체 Graph가 시작부터 보고서 생성까지 한 번 실행되어야 한다.

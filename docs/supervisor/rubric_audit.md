## 패턴과 State

[그래프](../../graph/supervisor.py)는 다섯 담당자를 모두 Supervisor로 연결합니다. 컴파일한 그래프에서도 각 담당자의 다음 노드가 Supervisor 하나인 것을 확인했습니다. [담당자 어댑터](../../agents/supervised.py)는 자기 결과와 Supervisor의 명시적 전달 자료로 입력을 구성합니다. 다른 담당자·제어 필드를 반환하면 계약 위반으로 처리합니다.

[Supervisor](../../nodes/supervisor.py)는 현재 적격성, 미수행 관점, 미확인 지표 수와 호출 예산을 읽습니다. 같은 실행에서 담당자를 다시 호출하는 경우에도 부족 지표와 사유가 전달됩니다. State에 따라 담당자 선택이 달라지는 테스트가 통과했습니다. 고정 스텝 수만으로 보고서 작성 여부를 결정하지 않습니다.

운영 실행에서 모든 후보의 근거 충분성은 미달이었습니다. 이 경우 종료 사유를 evidence_exhausted로 기록하고 HOLD와 확인 한계를 남겼습니다. 이를 근거 충분성 통과로 표시하지 않았습니다. 근거가 충분하면 상한 전에 종료하는 경로는 별도 테스트로 확인했습니다.

[State 스키마](../../schemas/supervisor.py), [기존 공통 State](../../schemas/state.py), [Reducer](../../graph/reducers.py), [SQLite 복원](../../graph/checkpoints.py)을 [설계 문서](design.md)의 일곱 항목과 대조했습니다. 담당자는 순차적으로 호출하며 제어 상태의 동시 쓰기는 발생하지 않습니다. 출처는 ID별로 중복 없이 병합하고 충돌은 거부합니다. 원문 PDF와 벡터는 State 밖에서 관리합니다.

## 품질 평가와 실패 처리

[품질 노드](../../nodes/report_quality.py)는 PDF가 생성된 다음 실행됩니다. 출처 연결, 중립성, 편향 통제, 네 관점과 파일 무결성을 규칙 기반으로 평가합니다. 과제의 평가 방식 1안을 선택한 구현이며 의미적 함의까지 자동 검증하는 LLM Judge는 아닙니다.

최신 코드로 [품질 결함 주입 시나리오](evidence/quality-repair/run.json)를 다시 실행했습니다. 평가 이력은 개정 0 미달, 개정 1 통과입니다. 실제 LangSmith 추적 ID는 `70274d27-8262-4962-b8e2-1559ad8bc89f`입니다. 정상 운영 실행은 최초 평가에서 통과했으므로, 그 실행에서 품질 재작성 루프가 발생했다고 주장하지 않습니다.

[작업 실패 시나리오](evidence/worker-retry/run.json)에서는 최초 Tech 호출에 TimeoutError를 넣고 다음 호출이 복구되는 것을 확인했습니다. 추적 ID는 `033d5cf0-c705-49fb-8404-419eea1cacdc`입니다. 두 시나리오는 의도적인 결함 주입이며 운영 LLM의 실제 오류와 구분합니다.

## 별도 체크아웃 재현

같은 코드의 별도 Git worktree를 만들었습니다. 이 체크아웃에는 로컬 `.env`와 기존 인덱스가 없었습니다. 다음을 확인했습니다.

1. manifest의 세 추가 원문을 다시 다운로드하고 SHA256을 확인했습니다.
2. 전체 테스트 223개가 통과했습니다.
3. 17개 문서, 200페이지, 255개 청크의 RAG 인덱스를 새로 만들었습니다.
4. API 키 없이 저장 근거와 실제 RAG를 사용하여 PDF를 생성했고 품질 통과 상태로 종료했습니다.
5. 기존 기준·초기 단계·Figure 비교 점수가 제출된 운영 기록과 일치했습니다.

의존성은 검증된 Python 3.11 환경을 재사용했습니다. 의존성 자체를 빈 환경에 다시 설치했다는 뜻은 아닙니다. 별도 체크아웃의 LangSmith 업로드는 끄고 실행했으며 trace_id는 로컬 연결 키입니다. 실제 LLM을 포함한 운영 추적은 `evidence/live`에 별도로 보존했습니다.

원본 확인 자료는 [점검 JSON](evidence/rubric-audit/audit.json), [별도 체크아웃 테스트](evidence/rubric-audit/clean-pytest.xml), [인덱스 생성 결과](evidence/rubric-audit/clean-index-build.json), [재현 실행](evidence/rubric-audit/clean-run.json), [재현 보고서](evidence/rubric-audit/clean-report.pdf)입니다.

## 제출 전 보완 사항

현재 PNG는 실제 LangSmith API 기록을 렌더링한 자료입니다. 과제 안내의 웹 화면 캡처와는 구분합니다. macOS의 Chrome 자동화 권한이 거부되어 웹 UI 촬영은 완료하지 못했습니다. 운영 실행과 품질 재작성 실행의 LangSmith 화면을 순서대로 캡처해 제출해야 합니다.

팀에서 확정한 Supervisor 실습의 역할 배분을 README의 Contributors와 [개발 역할분담](../개발_역할분담.md)에 반영했습니다. 품질 평가 노드는 김도현, 평가 결과에 따른 보고서 수정은 김진형, README 최종 취합은 김도현 담당입니다. 이 배분은 개인별 커밋 실적을 의미하지 않습니다. 웹 화면 확보 방법은 [캡처 안내](langsmith_capture.md)에 정리했습니다.

따라서 코드·실행 항목의 근거는 확보했지만, 전체 제출 준비가 모두 완료되었다고 판정하지는 않습니다.

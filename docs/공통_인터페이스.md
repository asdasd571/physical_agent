# 공통 인터페이스 1.0.0

이 문서는 김낙근, 김도현, 박세진, 김진형의 브랜치가 공유하는 코드 계약을 설명한다. 공통 모델 구현은 `schemas/`, 검색 진입점은 `rag/service.py`에 있다.

## 사용 원칙

- 각 담당자는 공통 모델을 자기 브랜치에 다시 정의하지 않는다.
- 필드 추가나 이름 변경이 필요하면 먼저 `schemas/`를 수정하고 팀에 공유한다.
- Agent는 State 전체가 아니라 담당 분석 결과와 새 출처만 반환한다.
- RAG는 검색 결과만 반환하고 지표 점수나 투자 판단을 만들지 않는다.
- `source_ids`는 반드시 State의 `sources`에 존재하는 `SourceRecord`를 가리킨다.

## 원값 기록 예시

검증된 0건은 숫자 `0`과 `SUCCESS`로 기록한다.

```python
IndicatorEvidence(
    id="M1",
    raw_value=0,
    unit="특허 패밀리",
    evidence_status=EvidenceStatus.THIRD_PARTY_VERIFIED,
    source_ids=["src_patent_search"],
    collected_by="competitor",
    query_status=QueryStatus.SUCCESS,
)
```

자료가 없으면 `None`과 사유를 기록한다.

```python
IndicatorEvidence(
    id="K2",
    raw_value=None,
    evidence_status=EvidenceStatus.NO_EVIDENCE,
    source_ids=[],
    collected_by="tech",
    query_status=QueryStatus.NO_DATA,
    missing_reason="30회 이상 실물 시험 결과를 찾지 못함",
)
```

접근 실패도 0으로 처리하지 않는다.

```python
IndicatorEvidence(
    id="F3",
    raw_value=None,
    evidence_status=EvidenceStatus.NO_EVIDENCE,
    source_ids=[],
    collected_by="discover",
    query_status=QueryStatus.ACCESS_FAILED,
    missing_reason="공식 조회 서비스 응답 실패",
)
```

## PDF Source 예시

```python
from datetime import datetime

SourceRecord(
    source_id="src_test_report",
    kind=SourceKind.PDF,
    publisher="Company A",
    title="Robot Hand Test Report",
    url="https://example.com/report.pdf",
    published_at=None,
    collected_at=datetime.now().astimezone(),
    local_path="data/documents/tech/company_a_report.pdf",
    sha256="a" * 64,
    doc_id="company_a_tech_001",
    page=12,
    chunk_id="chunk_test_report_12_01",
    evidence_excerpt="28 successful trials out of 30",
)
```

PDF Source는 `local_path`, `sha256`, `doc_id`, `page`가 필수다. API Source는 `response_id`가 필수다.

## RAG 호출 예시

```python
from rag import search_documents

results = search_documents(
    query="이 회사의 로봇핸드 실물 조작 성공률은?",
    candidate_id="company_a",
    doc_types=["tech"],
    top_k=5,
)
```

반환형은 `list[RetrievedChunk]`이며 각 결과는 다음 필드를 가진다.

```text
chunk_id
source_id
doc_id
candidate_id
doc_type
page
content
score
```

실제 인덱스를 준비한 뒤 애플리케이션 시작 시 검색 backend를 등록한다.

```python
from rag import configure_search_backend

configure_search_backend(hybrid_retriever)
```

backend가 등록되지 않은 상태에서 검색하면 Mock 결과를 반환하지 않고 `SearchBackendNotConfiguredError`가 발생한다.

|---|---|
| `run`, `candidates` | init |
| `candidate_index`, `current_candidate`, `control` | select_candidate |

| `eligibility` | eligibility_check |
| `tech_analysis` | tech |
| `market_analysis` | market |
| `competitor_analysis` | competitor |

| `evidence_review` | review |
| `evaluation`, `decision` | judge 또는 skip |
| `evaluations` | archive |
| `sources` | 모든 수집·분석 Node |
| `report` | report |

## 인터페이스 변경 규칙

1. 기존 필드의 의미를 바꾸지 않는다.
2. 호환되는 선택 필드 추가는 patch 또는 minor 변경으로 처리한다.
3. 필드 삭제, 이름 변경, 자료형 변경은 major 버전을 올린다.
4. 인터페이스를 변경한 사람은 `tests/test_schemas.py`를 함께 수정한다.
5. 변경 커밋을 `main`에 push한 뒤 각 담당자가 자기 브랜치에 `main`을 반영한다.

```bash
git switch feature/담당-브랜치
git fetch origin
git merge origin/main
```
